# DMVCN 六个月内容增长目标

制定日期：2026-07-24  
执行周期：2026-07-24 至 2027-01-24  
数据基线：Google Search Console 过去 28 天

## 一、长期目标

把 dmvcn.com 从“资料已经齐全的信息库”推进为“在美国中文用户遇到 DMV 问题时，能直接找到、看懂并回到政府网站办理的实用工具”。

六个月后同时达到以下结果：

1. 最近 30 天自然搜索点击不少于 500 次，曝光不少于 50,000 次，全站 CTR 不低于 1%。
2. 至少 30 个页面进入平均排名前 20，其中至少 15 个页面进入前 10。
3. 美国访问者贡献至少 70% 的自然搜索点击；非目标地区和泛英文查询不再主导曝光。
4. 每月完成 8 至 12 个高价值页面动作，其中至少一半是重写、补证据或提升可用性，不以新增页数为唯一目标。
5. 所有可索引页面继续通过站内 E-E-A-T、来源、结构、链接、SEO 和发布门禁检查。
6. 高风险新页面在真实人工语义复核前保持 `noindex,follow`，不进入 sitemap。

## 三、阶段目标

### 第 1 阶段：搜索意图校准（第 1-30 天）

目标：

- 最近 28 天曝光达到 10,000，点击达到 50，CTR 达到 0.5%。
- 完成 10 个高曝光页面的标题、摘要、开头答案和内部链接检查。
- 将没有独立搜索价值的工具页或来源页改为 `noindex`，但保留站内访问和审计用途。
- 建立可重复的 Search Console CSV 导入与月度优先级报告。

优先页面：

- `/directories/dmv-services/`
- `/directories/new-residents/`
- `/directories/costs-timing/`
- `/directories/service-paths/`
- `/topics/vehicle-registration-renewal-expired-tags-non-operation/`
- `/topics/lost-stolen-license-plates-registration-card-sticker/`
- `/topics/lost-vehicle-title-replacement-electronic-title-lien-sale/`
- `/topics/renewal-replacement-address/`
- `/topics/gift-inherited-vehicle-title-transfer/`
- `/states/new-jersey/`

### 第 2 阶段：形成问题主题群（第 31-90 天）

目标：

- 最近 30 天曝光达到 25,000，点击达到 200，CTR 达到 0.8%。
- 至少 15 个页面进入平均排名前 20。
- 每个高价值专题形成“专题页 + 优先州页 + 官方入口表”的内部链接闭环。
- 上线 3 至 5 个使用官方 Driver Manual 编写的州级中文笔试练习。

主题群：

1. 车辆 title：丢失、lien、赠与、继承、卖车、跨州转入。
2. Registration：续期、过期、sticker、车牌被盗、inspection、insurance hold。
3. 驾照与 ID：REAL ID、State ID、补证、改地址、姓名链、SSN / 非公民。
4. 考试：permit、笔试语言、路考车辆、陪同人、重考和 medical review。
5. 搬州：驾照转入、车辆登记、保险顺序、期限和旧州收尾。

优先州：

- Massachusetts
- Texas
- New York
- New Jersey
- Tennessee
- Kentucky
- California
- Florida
- Washington
- Georgia

### 第 3 阶段：扩大稳定流量（第 4-6 个月）

目标：

- 最近 30 天曝光达到 50,000，点击达到 500，CTR 达到 1%。
- 至少 30 个页面进入平均排名前 20，15 个进入前 10。
- 至少 10 个州形成“总览 + REAL ID + 笔试练习 + 3 个高频事项”的完整内容组。
- 通过 Search Console 识别并合并重复意图页，持续降低无效曝光比例。

## 四、固定执行节奏

每周：

1. 导出 Search Console 页面、查询、国家和设备数据。
2. 更新页面与查询映射，并运行 `npm run plan:sc` 与 `npm run plan:growth`。
3. 只有 `dataSnapshot.readyForPlanning` 为 `true` 且 `execution.allowedNow` 大于 0 时，才从执行队列取内容任务。
4. 泛英文或本地查询只进入观察队列；目标查询至少有 1 次点击或合计 5 次展示才成为内容候选，没有页面级证据时先补映射。
5. 查询落错页或多个页面承担同一意图时，先检查内部链接、页面分工、合并和重定向，不据此扩写当前页面。
6. 更新 2 至 3 个现有页面，或更新 2 个现有页面并新增 1 个明确需求页面。
7. 运行全部来源、E-E-A-T、SEO、链接、移动端和发布检查。

每月：

1. 对比最近 28 天与前 28 天的点击、曝光、CTR 和排名。
2. 记录美国、移动端、中文查询和非目标地区的变化。
3. 从数据中选择下月 8 至 12 个动作，并给每项指定官方来源和复核日期。
4. 分批运行 `npm run audit:links`，直到月度官方 URL 覆盖达到 100%，再运行 `npm run audit:source-freshness`。
5. 对 404、410 和异常跳转查找官方替代入口；403、限流和超时按域名记录，不直接当作失效。
6. 检查州政府规则变化和高风险页面复核状态。
7. 对连续两个月无目标曝光、无内部价值的薄页执行合并、`noindex` 或删除。

## 五、内容验收标准

每次发布必须满足：

- 页面解决一个明确问题，开头能让读者判断自己该走哪条路。
- 所有费用、期限、资格、材料、法律后果和身份要求能对应到当前政府来源。
- 高风险事实在正文附近显示来源，不只在页尾列链接。
- 有材料清单、办理步骤、常见失败原因、州别差异和政府办理入口。
- 首次发布日期、最后修改日期和最后事实核对日期真实且各自准确。
- 作者统一使用“DMVCN 官方编辑”，不虚构资历、亲身经历或专业审核。
- 通过 `npm run verify:launch`，并完成桌面与移动端页面检查。

## 六、停止规则

以下情况不新增页面：

- 现有页面已经完整覆盖相同搜索意图。
- 找不到足够的当前政府来源。
- 只能把政府原文简单翻译成中文，无法提供判断路径或实际办事价值。
- 页面依赖未经确认的州别推断。
- 高风险内容没有完成要求的真实人工语义复核。
- Search Console 快照、查询导出或页面查询映射超过 7 天。
- 本周或本月内容动作已经达到上限，或候选只有泛英文曝光。
