# 移动端性能标准

## 目的

Search Console 的 2026-07-24 分段快照显示，移动端只占 6.5% 曝光，却贡献 56.3% 点击，CTR 为 2.7%。因此移动端不是次要适配对象，而是美国中文用户增长的基准体验。

静态预算负责阻止可预防的资源和可访问性退化；Lighthouse 负责在真实浏览器中抽查渲染表现。两者都不能代替 Search Console Core Web Vitals 的真实用户数据。

## 发布预算

| 项目 | 上限 | 说明 |
| --- | ---: | --- |
| 页眉标志 | 8 KB | 页面实际显示 36px，使用 72px PNG 支持高像素密度屏幕 |
| Apple touch icon | 12 KB | 使用独立 180px PNG，不加载 512px 结构化数据原图 |
| 单个 CSS 文件 | 60 KB | 按未压缩构建文件计算 |
| 单个 JavaScript 文件 | 20 KB | 按未压缩构建文件计算 |
| 全站构建 JavaScript | 100 KB | 不包含页面内联数据 |
| 可索引页面 HTML | 600 KB | 按未压缩 HTML 计算 |
| noindex 页面 HTML | 1,100 KB | 仅允许来源台账等工具页使用较高上限 |

全部 `<img>` 必须有 `alt`、`width` 和 `height`。页面不得把 512px 原始标志用作页眉图片或浏览器图标，不得引入阻塞渲染的第三方脚本或样式。品牌链接的可访问名称必须包含可见文字，小标题颜色在站内三种背景上的对比度不得低于 4.5:1。

发布前执行：

```bash
npm run build
npm run audit:performance
```

## 2026-07-24 基线

修复前，生产站每页下载 196,629 字节的原始标志。模拟移动设备的代表页面总传输量如下：

| 页面 | 总传输量 | Performance | Accessibility | CLS |
| --- | ---: | ---: | ---: | ---: |
| 首页 | 224 KB | 100 | 96 | 0 |
| 德州总览 | 214 KB | 100 | 100 | 0 |
| 纽约州 REAL ID | 214 KB | 100 | 100 | 0 |
| 费用和拿证时间 | 246 KB | 100 | 100 | 0 |

首页另一次使用 DevTools 慢速移动网络得到 Performance 92、FCP 2.7 秒、LCP 2.7 秒。Accessibility 96 来自三处文字对比度不足；四个页面都存在品牌链接可访问名称与可见文字不一致。

候选构建把页眉标志降到 3,434 字节、touch icon 降到 5,768 字节。相同 Lighthouse 模拟配置下，四页总传输量分别降到约 35 KB、25 KB、25 KB 和 58 KB，品牌名称与颜色对比检查均不再报错。最终仍须在生产部署后复测，不能用本机响应时间代替生产结果。

## 月度复核

每月 Search Console 复盘时同时查看 Core Web Vitals 的移动端报告。出现“较差”或“需要改进”的 URL 组时，先按受影响模板和真实流量排序，再用生产 URL 复测 LCP、INP、CLS 和资源瀑布。没有真实用户样本时只记录为“数据不足”，不宣称通过真实用户体验验收。
